# ADR 006: 冻结页离线导出——周期窃取、微量分摊与原子回收

> 日期：2026-05-23
> 状态：定稿
> 性质：Feelings-OS 内存回收与持久化

---

## 问题——终极税务

为了留存 Post-Mortem 证据而冻结的原始数据物理页，不能永远占着内存。多熔断几次，mempoold 空闲链表会被历史尸体吃光，引发内存窒息。

但回收动作如果重了——总线争抢（Bus Contention）→ 下一帧的确定性被毁。回收如果轻了——内存不够用。必须在感官上完全不可感知的状态下完成回收。这是单地址空间硬实时系统避不开的终极税务。

## 核心策略——寄生在 Slack Time 里

正常运行期（Epoch 恢复后）的 1ms 物理窗口。animi 计算下一帧在某个确定时刻完成——不会撑满 1ms。

```
 0ms             0.4ms                                                 1.0ms
  ├───────────────┼──────────────────────────────────────────────────────┤
  │  P1 感受域     │                    P2 后台非实时域                    │
  │ (animi忙计算) │ (schedulerd 唤醒 logd，利用这 0.6ms 微量搬运)         │
  ▼               ▼                                                      ▼
总线极度繁忙     总线绝对空闲 ──► 每帧搬 64 字节 ──► 搬完立即收手 ──► 等下一帧

Δ_frame(1ms) = Δ_critical(0.4ms) + Δ_slack(0.6ms)
```

schedulerd 在时序上卡死：一旦 animi 提交了当前帧的缓冲页，立刻剥夺 P1 域执行权，把剩余时间扔给 P2 域的 logd。logd 只在总线地盘完全干净的时候才睁眼干活。

## 两条物理防线

### 防线一：低优先级周期窃取 DMA

不使用 Burst DMA——突发传输会死锁总线好几个微秒。只配一条硬编码低优先级的单字 DMA 通道。

```
总线仲裁优先级
    P0 安域中断      最高。不可抢占。
    P1 感受域        animi 计算 + busd 锁存。
    timerd           时钟脉冲。低于 P0/P1，高于后台。
    P2 周期窃取 DMA  最低。logd 搬运冻结页。

高优先级总线请求到达 → 总线仲裁器在 1 个时钟周期内无条件挂起 DMA →
把总线出让给实时任务。即使此时正在周期窃取中间——
突发熔断也能在 1 拍内切回安全态。
```

### 防线二：时间片颗粒化

logd 绝不在一帧内搬完一整页（假设 16KB）。每帧只搬 64 字节。

```
一帧内的搬运流程

    0.4ms       schedulerd 确认 P1 完成 → 注入 P2 当前可用 Δ_slack 预算
                logd 拿到 P2 启动令牌

    0.41ms      配置微量 DMA 计数器（< 50ns）
                logd 不动用 CPU 复制——只把冻结物理页的
                Current_Offset 赋给低优先级 DMA，
                设置传输计数器 = 固定值 64 字节，
                目标地址 = 物理黑匣子 FIFO（eMMC / SPI Flash 缓冲）。

    0.41-0.95ms 物理周期窃取传输
                DMA 在总线空闲空隙里一字一字地偷。
                单字传输 + 最低优先级 =
                即使此时突发紧急熔断，
                总线也能在 1 拍内切回安全态。

    0.95ms      时钟断头台
                下一拍硬时钟脉冲到来的前 50μs——
                schedulerd 强行切断 P2 域。
                不论 64 字节搬没搬完——
                DMA 控制器被硬件强制 Freeze。
                给下一帧腾出绝对干净的物理战场。
```

如果 64 字节在 0.95ms 之前已经搬完——logd 提前收手。剩下的 slack 作为静默余量，不调度任何新操作。

## 原子状态字——Physical Page 的全局控制块

每个被管理的物理页在 mempoold 的全局控制块里，由一个 32 位原子状态字管辖。

```
 32位原子状态字位域布局：
 ┌──────────────────────────────┬───────────────┬───────────────┐
 │ bit[31:16]                   │ bit[15:8]     │ bit[7:0]      │
 │ Frozen_Epoch_ID (熔断时Epoch)│ Transfer_Flag │ Page_Status   │
 └──────────────────────────────┴───────────────┴───────────────┘

Page_Status 取值
    STATUS_ACTIVE        0x01    正常使用中
    STATUS_FROZEN_RO     0x02    冻结——只读（MPU 写权限已拉低）
    STATUS_DRAINING      0x03    logd 正在搬运（Transfer_Flag > 0）
    STATUS_DRAINED       0x04    搬运完成——等待物理回收
    STATUS_MUTATED       0x05    搬运中断——被二次熔断打断

Transfer_Flag
    0x00    搬运未开始
    0x01-0xFE 当前搬运偏移量（以 64 字节块计）
    0xFF    搬运完成
```

## 原子回收——零锁两步翻转

### 步骤一：logd 发出 CAS，翻转状态

当一页的最后一字节被 DMA 搬完——Transfer_Flag 到达 0xFF——logd 在 P2 域结尾发出一条原子 CAS 指令。

```
CAS(
    addr  = &page->atomic_status_word,
    old   = STATUS_FROZEN_RO | (Frozen_Epoch_ID << 16),
    new   = STATUS_DRAINED | (Frozen_Epoch_ID << 16)
)

成功 → 页从冻结只读翻转为已导出待回收。
失败 → 说明该页在搬运期间被二次熔断改写（见下文"搬运中途二次熔断"）。
        logd 跳过——不回收。下次再查。
```

### 步骤二：mempoold 后台清洗

mempoold 的后台无序清理循环——极低优先级，只有当空闲链表低于安全水位时才被触发。

```
遍历全局页控制块表
    ↓
[ 某页 Status == STATUS_DRAINED ? ]
    │
    ├── Yes → 硬件物理块擦除（内存全零化指令）
    │         MPU 权限恢复为 RW
    │         页挂回空闲链表末尾
    │
    └── No  → 跳过。继续遍历。

一次只清一页。
不清多——防止突发总线负载。
```

## 搬运中途二次熔断

logd 正在搬 Epoch_01 的冻结页。第 50 帧，二次熔断，Epoch 翻到 02。

```
HardFault 瞬间

    1    全局 Current_Epoch_ID 原子加 → 0x02
         mempoold 全局控制块里产生新冻结页（Epoch_02 的原始数据）

    2    logd 被上下文劫持（和 animi 一样——PC 被重写到 reset 入口）
         但 logd 的劫持更温和——它只需要放弃当前搬运。
         不需要做 animi 那种全状态机清洗。

    3    旧页（Epoch_01）的 Transfer_Flag < 0xFF →
         该页原子状态立即翻转为 STATUS_MUTATED。
         MUTATED 页与 FROZEN_RO 共存于冻结链表——
         但优先级被降级。

新尸体优先原则

    logd 在 Epoch_02 的 P2 域醒来后
    → 查询 mempoold 冻结链表
    → 发现两个 Epoch 的页
    → 先搬 Epoch_02（新尸体）的新页
    → Epoch_01 的 MUTATED 残留页 ——
      等系统彻底进入长周期稳定后，
      P3 域（真正空闲到发慌时）再回头搬。
```

## 回收优先级——最老的 Epoch 最后回收

冻结页链表的回收顺序不是 FIFO——是 LIFO（后进先出）。

```
原因
    最近一次熔断的原始数据 → 离线诊断价值最高。
    它是导致当前 Epoch 慢启动爬坡的直接原因。
    Post-Mortem 分析首需。

    最早一次熔断的原始数据 → 历史价值。
    但当前 Epoch 的诊断优先级高于历史复盘。

回收顺序
    1. 当前 Epoch 稳定后 → logd 先搬最近一次熔断的冻结页
    2. 搬完后 → 逆序遍历更早 Epoch 的 MUTATED 残留页
    3. 全部搬完 → P3 域空闲时搬最早的历史冻结页
```

## 极端场景——冻结页吃光内存

如果熔断频率极高，冻结页链表长到空闲链表低于危险水位——P0 域在保底帧期间启动紧急回收。

```
触发条件
    mempoold 空闲页数 < 安全水位线的 20%

紧急回收（P2 域正常回收的降级路径）
    1. 从最早 Epoch 的 MUTATED 页中——挑 Transfer_Flag 最大的。
       即搬运进度最接近完成的那些页。

    2. 对这些页执行加速搬运
       仍然用周期窃取单字 DMA——
       但每帧搬运量从 64 字节提升到 256 字节。
       仍不是 Burst——仍然可以被总线仲裁器在 1 拍内打断。

    3. 加速搬运持续到空闲链表回到安全水位以上。
       一旦达标 → 立刻回到正常 64 字节/帧。

    4. 如果加速搬运仍追不上熔断产生的冻结页速度
       → 系统应进入降级运行模式
       → 限制 animi 的输出强度 → 降低再次熔断的概率
       → 这不是内存问题——这是在告诉上层：
         "故障频率太高。先稳住。别急着恢复。"
```

## 总结

Feelings-OS 的离线导出本质上是一种高级的时间寄生。它利用帧空闲的 0.6ms——那段时间在电生理尺度上毫无意义，但在数字系统尺度上是奢侈的白嫖窗口。logd 像个贼一样在总线闲暇时几十字节地偷数据。肉身完全无感。黑匣子在几百帧的微量分摊后，完整地出现在了外部持久化存储上。
