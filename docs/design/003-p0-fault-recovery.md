# ADR 003: P0 安全域——熔断、保底与慢启动恢复

> 日期：2026-05-23
> 状态：定稿
> 性质：Feelings-OS 安全底座

---

## P0 中断触发——物理线直连

```
0.8ms   后颈 ACK 未到。
        busd 硬件看门狗计数器归零。
        硬件中断线拉高。
        schedulerd P0 中断向量入口。

0.81ms  P0 处理程序就位——不到 1μs。
```

P0 中断线和 100μs 安域抢占是同一条物理通路。不经过任何软件路由。

## P0 处理程序——顺序不可协商

```
第一步   总线数据归零
        迷走神经刺激输出 = 0mA
        后颈振动 = 0
        腕部温度 = 维持当前值（不降到危险低温，不升到热损伤）
        全部设备的输出寄存器在 1 个总线周期内批量清零。

第二步   未完成帧标记为 Stale → 丢弃
        这一帧参数基于上一帧生理反馈。
        上一帧反馈可能已从故障设备断裂。
        错误反馈上的下一帧参数 = 不可信。
        不补发。不重试。直接丢弃。

        为什么不能补发
            迷走神经和 CT 纤维的受体有去敏感化周期。
            后颈设备在 0.8ms 没收到信号 = 物理通道错过最佳去极化窗口。
            如果在第 2ms 把这一帧"补发"过去——
            神经元相位已变 → 高概率触发异常强直 → 痉挛/惊厥。

第三步   保底帧接管
        不是零输出。是编译期硬编码的安全基线帧。
        迷走神经回到最低安全张力维持水平。
        CT 纤维回到基础触觉基线。
        心率、皮电、呼吸监测继续跑。
        不再走 animi 任何实时交织管线。

第四步   日志写入
        logd 追加 hard_fault 记录：
        时间戳、故障设备编号、总线状态快照、当前 Epoch_ID、帧号。
        后续 post-mortem 用——现场不分析。
```

## 10ms 保底帧——给肉身的物理缓冲垫

```
为什么要 10ms，不是立即回到 animi 控制？

零输出 = 危险   突然的"零信号"在生物学上等同于感官剥夺或传导阻滞。
                会瞬间诱发杏仁核的最高级别应激——以为自己瘫痪了。
                交感神经暴走 → 皮质醇骤升 → 心率飙升。

保底帧做的事    迷走神经——维持最低张力。
                CT 纤维——维持基础触觉基线。
                植物神经——继续接收微弱信号，确认系统没死。

10 帧（10ms）   不是随意选的。
                神经元对去极化的完全不应期约 1-2ms。
                但自主神经系统的交感-副交感振荡周期约 3-5 次/秒。
                10ms 足够覆盖多个完整振荡周期——
                系统在恢复时不会撞上任何神经振荡的敏感相位。
```

## 慢启动（Slow Start）——膜信任的重新积累

```
刺激强度 (mA)
  │
  │      X (故障发生)
  ├──────┐
  │      │
  │      └───────────┐ [10ms 保底基线——强度 = 安全最低值]
  │                  │  ▲
  │                  │  │ 慢启动爬坡 (Trust Accumulation)
  │                  └──┴────────────────────────► 时间 (ms)

第 11 帧        慢启动开始。强度 = 5/100。

第 11-30 帧     每一帧总线全通且全部 ACK →
                强度许可上调 1 档。
                30 帧后 → 强度回到 25/100。

第 30-100 帧    加速爬坡。每 5 帧全通 → 上调 1 档。
                100 帧后 → 强度回到 70/100。

第 100+ 帧      接近原始强度区间。
                进入线性爬坡 → 每帧微调 1 档。
                直到回到熔断前的原始强度——
                或者校准参数被二次熔断标记为去信任化后停止爬坡。
```

## 二次熔断——去信任化

如果同一个设备在同一个 Epoch 恢复过程中再次熔断。

```
第一次熔断    保底帧 10ms → 慢启动爬坡 → 恢复。
            静态校准参数保留（Freeze）。

第二次熔断    再次触发同一设备 → 该设备的静态校准参数
            → 标记为 "待重新验证"（De-trusted）。

第三次慢启动  不是继续爬回原来强度。
            只发 1% 强度的测试脉冲。
            反向推算硬件的真实阻抗和物理参数。

            通过测试 → 重新校准参数 → 恢复。
            未通过测试 → 该通道永久降级为 OUTLINE 模式。
            保全其他完好通道。
```

## Epoch 机制——每次熔断全局世代号自增

```
熔断瞬间       mempoold 管理的全局 Epoch_ID 自增（单字原子加）。
              帧缓冲页元数据区写入新 Epoch_ID。

animi 复位后    读取全局 Current_Epoch_ID。
                所有发出的帧必须打上匹配的 Epoch 标签。
                busd 硬件比对——不匹配 → 拒收。

                              第 11 帧——

animi 状态机    SAFETY_HOLD 状态。
                观察 0xDEAD_FRAME_CTX 的 bit[6:15]——保底帧计数。

                计数到达 10 → 自动切到 SLOW_START。
                SLOW_START 下：
                    强度 = 5/100
                    感受类型 = calm_baseline（安全基线包）
                    不调用 PBM 个人化偏移
                    不调用设备分配矩阵
                    只走一条编译期硬编码的安全交织通路
```
