# ADR 001: 单一地址空间与 MPU 物理隔离

> 日期：2026-05-23
> 状态：定稿
> 性质：Feelings-OS 内存架构基础，不可降级

---

## 决策

采用**单一地址空间（SAS）+ MPU 物理边界**，放弃 MMU 虚拟内存。六个守护进程共享同一块物理连续内存，通过 MPU 在硬件层锁死各自的读写边界。

## 为什么不是 MMU

```
MMU                            MPU
───                            ───
虚拟内存翻译                    纯物理地址，只设访问权限
页表（4KB 粒度）                区域（任意对齐，粗粒度到几 MB 均可）
TLB 刷新 → μs 级延迟            零延迟——硬件在地址总线上直接比对
多级页表 → 缺页中断              无——物理连续意味着地址永不换
内核态/用户态切换存在             无内核无用户——单地址空间
```

MMU 的本质是用虚拟地址的"谎言"换取灵活性。Feelings-OS 不需要任何灵活性——它只要绝对的确定性。每 1ms 一帧——TLB flush 带来的 μs 级抖动不可接受。

## MPU 区域划分

六个守护进程，六个 MPU 区域。加上共享区域。

```
进程         MPU 配置
────         ────────
mempoold     RW 自己的内存池管理区。只读其他进程的分配状态表。
schedulerd   RW 调度表和 TCB 区。可读其他进程的寄存器快照区。
cached       RW 缓存映射区。不可碰 mempoold 控制块。
busd         RW 总线寄存器。不可碰其他任何区域。
timerd       RO PLL 硬件计时器。RW 时钟分发页。
logd         RW 日志追加区。不可读写其他任何区域。

共享区
    /dev/* 帧缓冲页    每块页只有两个 MPU 授权：
                      写入者（animi 或驱动）— RW
                      读取者（busd 或设备）— RO

    安全状态页（0xDEAD_FRAME_CTX）
                      P0 中断处理程序 — RW
                      animi — RO
                      busd — RO
```

## 硬件熔断——零周期违规检测

```
[ CPU 发出物理地址 ] ───→ [ MPU 硬件比较器 ] ───→ [ 内存总线 ]
                                 │
                                 └── 非法越界 ──→ [ HardFault ]
                                                   │
                                                   └──→ P0 安全域接管 < 100μs
```

MPU 的比较器直接挂在地址总线上。比对开销 = 零周期。越界 = HardFault，直接跳转 P0 中断向量——不经过任何软件分支。

cached 因为野指针碰了 mempoold 的控制区 → 不等指令执行完 → 硬件直接拦截。

## 和微内核的对比

微内核仍然有内核空间这个概念本身。即使精简到最小——仍然需要系统调用、IPC、内核态/用户态切换。Feelings-OS 不需要——因为没有哪个进程是"内核"。schedulerd 和 mempoold 是特权进程，但它们和 cached 跑在同一块物理内存上，不在任何其他地址空间之上。没有页表切换。没有消息队列。进程之间只有帧缓冲页。

## 编译期 + 硬件层双层防护

```
Rust 编译期     所有权模型 → 借用检查和生命周期在编译时杜绝悬垂指针。
                零 unsafe（除非 FFI 边界到 C 驱动）。

MPU 硬件层      C 驱动层的 volatile 指针越界 → MPU 直接拦。
                不等到执行完那条指令 → 总线异常 → P0 接管。
```

两层防护。软件层错误在编译期被拦。硬件层错误在总线上被拦。
