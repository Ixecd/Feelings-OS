# ADR 004: 上下文劫持——P0 对 P1 的异步复位

> 日期：2026-05-23
> 状态：定稿
> 性质：Feelings-OS 调度器安全机制

---

## 为什么不能通知

在 SAS 且硬实时约束下，传统异步信号全部失效。

```
Unix 信号（kill/SIGSTOP）
    建立信号栈 → 复制上下文 → 不可控的时间抖动。
    在 1ms 帧预算内——不可接受。

IPC 消息
    消息队列 → 发送 → 接收 → 确认。
    animi 必须先"停下当前计算"才能去查消息。
    停下本身需要几十个周期。
    在保底帧期间 animi 被挂起——根本不消费消息。

轮询标志位
    animi 每一帧开始前主动读标志页。
    这个可以做——但在"故障瞬间"依赖它不够。
    P0 不能等 animi 自己查到——它此刻可能正在执行一条
    计算指令，下一拍才轮询。
```

## 上下文劫持——直接改 TCB

在 0.81ms HardFault 发生后，P0 中断处理程序不叫醒 animi——直接在已经被硬件压栈的 TCB 上下文上做手术。

```
硬件自动压栈的内容（HardFault 发生时 CPU 自动保存）
    PC       程序计数器——下一条该执行的指令地址
    R0-R12   通用寄存器
    R13(SP)  栈指针
    R14(LR)  链接寄存器
    R15(PC)  (同上)
    PSR      程序状态寄存器（N/Z/C/V 条件码 + 当前模式位）

schedulerd 在 10ms 保底帧期间对这块上下文做的手术

    PC  ← animi_reset_vector
           将下一条指令地址直接重写为 animi 的复位入口。
           恢复执行时——anim 直接从复位函数开始跑。

    R0  ← 0xDEAD_BEEF
           故障码。告诉 animi 这不是正常启动——
           是 P0 强制复位。原因是总线断裂。

    PSR ← 条件码全清零
           [关键] 如果不清零——
           保存的上下文里可能有上次比较的残留条件码。
           animi 复位后第一条指令如果是条件跳转——
           例如 BEQ .setup_loop——stale 的 Z=1 直接跳飞。

    其余寄存器   不碰。值在复位函数的第一件事就是整体清空。
```

## 为什么连 PSR 条件码也要清——执行残影

```
异常前最后一拍
    animi 执行: CMP R1, R2
    结果导致 Z=1 (R1 == R2)

0.81ms 熔断
    HardFault 压栈。PSR(Z=1) 被固化在上下文里。

10ms 保底期
    schedulerd 改了 PC 和 R0。
    但没有清 PSR——Z=1 残留在上下文中。

第 11 帧恢复
    animi 站在 reset_vector 入口。
    如果复位引导为了极速初始化，使用条件跳转：
        BEQ .setup_loop    ← 此时 Z 仍为 1！直接跳飞。

    而 .setup_loop 的地址可能是完全错误的内存区域。
```

修正：schedulerd 劫持 TCB 时，PSR 条件码位（N/Z/C/V）全部硬抹为 0。

## animi 复位后的状态机清洗

被"一鞭子抽醒"的 animi 进入 `animi_reset_vector` 后，必须在 < 0.5ms 内完成内部状态的物理剪枝。

### 内存剪枝

```
数据类型              处置          原因

预测矩阵              零化          基于平滑连续性推演的 Kalman 梯度
( Predictive Matrix )              趋势已断裂。保留 = 信号输出畸变。

生理反馈积分器         重置为基线    过去积累的心率、皮电变化积分全部清零。
( Biometric Integrators )          防止重连后积分饱和（Windup）→ 暴冲。

静态校准参数           保留          用户的安全阈值底线、硬件通道的绝对增益
( Static Calibration )  ( Freeze )   上限。这些是死脑筋，死都不能丢。
                                    [例外：二次熔断时标记为去信任化]

帧缓冲页               全部清空      当前正在填充的页 → 归零。
                                   重填从保底基线开始。
```

### 管线降级

animi 的八 Pass 交织管线立即关闭所有高阶 Pass，收缩到最基础的两条：

```
生理体征监控 Pass     继续读取心率/皮电/呼吸——只读不调。
低阶信号平滑 Pass     只发编译期硬编码的安全基线参数。
                    不调 PBM。不调设备矩阵。不走任何预测分支。
```

## animi 状态机的恢复期状态

```
SAFETY_HOLD
    进入条件    PC 和 R0 被劫持后首次苏醒。
    行为        只读取 0xDEAD_FRAME_CTX。
                观察 bit[6:15]——保底帧计数。
                计数未到 10 → 不产生任何输出帧。

SLOW_START
    进入条件    保底帧计数 = 10。
    行为        强度 = 5/100。
                感受类型 = calm_baseline。
                不调用 P6/P7。走硬编码安全通路。

                每一帧检查 busd 状态：
                故障设备未恢复 → OUTLINE 模式。
                故障设备已恢复 → 线性爬坡。

CALIBRATION
    进入条件    爬坡接近原始强度。
    行为        逐帧微调。总线全通连续 3 帧 → 上调 1 档。
                二次熔断 → 标记设备 → 探测模式。
```

## 软硬件步调对齐

```
硬件层（busd）
    总线物理输出上限 = 当前慢启动百分比。
    animi 送来 100% 强度的帧 → 压制到 5% 发出。

软件层（animi）
    状态机进入 CALIBRATION。
    不再调动用户情绪——乖乖按底层限制计算当前百分比强度。

握手爬坡
    连续 3 帧总线全通 + 全部 ACK →
    animi 内部状态机允许将输出增益放宽到下一档。
```
