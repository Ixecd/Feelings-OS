# ADR 002: busd——硬件 Ping-Pong 时序指挥官

> 日期：2026-05-23
> 状态：定稿
> 性质：Feelings-OS 总线架构基础

---

## 决策

busd 不是 DMA 控制器。不是数据搬运工。是**硬件时钟驱动的 Ping-Pong 状态机**——驻留在固定物理地址上，管理帧缓冲页的读写相位切换。

数据本身在帧缓冲页里。animi 写。从设备读。busd 只保证两者在同 1ms 内不碰同一块页。

## 物理布局

```
PLL 主时钟（timerd 管理）
├── 主设备（耳后）时钟广播 ← busd 的唯一时钟源
│   ├── 帧缓冲页 0（耳后刺激参数）
│   ├── 帧缓冲页 1（后颈刺激参数）
│   ├── 帧缓冲页 2（腕部刺激参数）
│   └── 帧缓冲页 3（颞部刺激参数）
│
├── 从设备 1（腕部）
├── 从设备 2（后颈）
└── 从设备 3（颞部）
```

## 1ms 帧预算

```
 0ms                         0.1ms                                       1.0ms
  ├───────────┬────────────────┬───────────────────────────────────────────┤
timerd脉冲   busd原子锁存     从设备物理拉取 (DMA/Register)                animi计算下一帧
            (页指针翻转)     [ 这一帧的神经信号绝对不允许任何抖动 ]          (填入备用页)
```

每 1ms：
1. timerd 脉冲 → busd 锁存当前帧缓冲页 → 原子翻转 Ping-Pong 指针
2. 主设备广播数据就绪 → 从设备各自拉取
3. 全部设备 ACK → busd 置 done flag → 下一拍

## 无锁双缓冲

```
第 N 帧      animi 在向 Page_A 写入下一组刺激参数
             从设备正从 Page_B 读取当前帧参数

时钟脉冲到来  busd 在一个总线周期内将全局指针从 Page_B 翻转到 Page_A

第 N+1 帧    animi 在向 Page_B 写入
             从设备正从 Page_A 读取

读写永远在两条绝对平行的物理轨道上。
没有锁。没有互斥量。
只有硬件时钟在无情地推着指针往前跳。
```

## 硬件看门狗

busd 在 0.1ms 广播数据就绪的同时，启动每个从设备的硬超时窗口。

```
后颈设备超时窗口     0.7ms（从 0.1ms 到 0.8ms）
                    不是软件定时器——是挂在总线上的硬件计数器。
                    计数器归零 → 硬件中断线拉高。
                    不经过任何软件层。
                    直接连到 schedulerd 的 P0 中断向量入口。
```

## Ping-Pong 页交替

```
正常帧
    Page_A = 当前活跃（从设备读取）
    Page_B = 上一帧（animi 正在覆写）
    时钟脉冲 → Page_A/B 指针翻转
    注意       从设备在读取期间，animi 绝不可写同一页。
               Ping-Pong 保证这种情况在物理上不可能发生。

异常帧
    0.8ms 某从设备未 ACK → 看门狗超时 → P0 接管
    当前 Page_A 的数据 = 不可信 → 直接标记 stale → 丢弃
    不补发       这一帧参数基于上一帧生理反馈。
                 上一帧反馈可能已从故障设备断掉。
                 旧参数补发 → 神经元异常强直。
    不重试       再等 0.2ms 不会改变物理事实——线断了就是断了。
```

## 帧头硬标签与硬件级拒收

帧缓冲页的前 8 字节不是刺激参数。是帧头。

```
帧缓冲页头部（前 8 字节）
┌────────────────┬────────────────┬───────────┬─────────────────────┐
│ bit[0:7]       │ bit[8:15]      │ bit[16]   │ bit[17:23]          │
│ Epoch_ID (0x02)│ Frame_Seq_Num  │ SS_ACTIVE │ Slow_Start_Percent  │
└────────────────┴────────────────┴───────────┴─────────────────────┘
        │
        ▼  (busd 硬件直接比对总线内部 Current_Epoch_ID)
[ busd 锁存比较 ] ───( Mismatch! )───► 物理拒收

animi 复位后可能发出旧 Epoch 标签的帧 → busd 比对失败 →
那一帧根本没有离开缓冲页。总线上没人看到。
```

## 非对称信任

上层可以千疮百孔。底层只需一招御敌。

animi 的复位代码可以写崩。可以发出前朝的旧数据。busd 的硬件比较器在几个周期内看到 Epoch_ID 对不上——直接拒收。数据出不了缓冲页。总线链路上毫无动静。

不信任上层。只信任自己和硬件计数器。
